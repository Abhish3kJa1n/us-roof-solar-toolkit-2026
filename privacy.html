Information entered into calculators

The original roof, combined roof-and-solar and savings calculators perform their calculations in the visitor's browser. Their code does not intentionally submit household electricity use, roof measurements, installer quotes, tariff values or financing assumptions to a Roof & Solar Toolkit application endpoint. Website hosting and CDN providers may nevertheless process technical request data such as IP addresses, requested URLs, browser details and timestamps.

City/state place lookup and solar production estimator

When a visitor uses the city lookup, the city or Census place name and selected state abbreviation are sent to this website’s same-origin location endpoint. The endpoint queries the U.S. Census Bureau TIGERweb Current (2026) service for matching incorporated places and Census-designated places. It returns the place name, geography type, Census identifier and internal representative latitude/longitude point. If multiple place matches are returned, the visitor chooses one. This is not a street address, parcel or rooftop coordinate and does not establish a utility service territory or permit jurisdiction.

When the visitor requests a PVWatts estimate, the selected representative coordinates and visitor-entered system capacity, tilt, azimuth and system-loss assumptions are sent to this website’s same-origin server endpoint. If the owner has configured the NLR PVWatts API key and shared D1 request-quota database, that endpoint forwards the model inputs to the National Laboratory of the Rockies (NLR) PVWatts V8 API. The API key is stored as a server-side secret and is not intentionally sent to the visitor’s browser. The estimator does not request a street address, utility account number, electricity bill, annual household consumption or installer quote.

The page also loads a bundled state-level EIA residential electricity-price CSV after a Census place is selected. This static reference file is delivered by the website; it is not a third-party lookup request and its statewide average is not the visitor’s utility tariff. The site also loads `data/price-benchmarks.json`, a public same-origin static file containing only source-reviewed historical price-reference records (currently no approved records). No visitor-entered address, city, quote, roof measurement, electricity usage or tariff is included in that request.

Nearby utility-rate records

The optional nearby-rate lookup sends the selected representative latitude and longitude to this website's server-side endpoint. If the owner has configured an OpenEI API key and the shared D1 request-quota database, the endpoint sends those coordinates to the OpenEI Utility Rate Database and returns nearby residential rate records. The records are candidates only; they do not establish which utility or tariff applies to a home. Do not treat them as selected or verified billing rates. If this API integration has not been configured, the lookup returns a not-configured message and does not query OpenEI.

Third-party and hosting services

Intended service integrations in this prototype are Cloudflare Pages/Functions for site delivery and same-origin endpoints, US Census Bureau TIGERweb Current for city/state place lookup, NLR PVWatts V8 for solar-production modeling, and OpenEI URDB for optional tariff-record discovery. PVWatts and OpenEI each require an owner-configured server-side API key and the shared D1 quota binding. Before deployment, review the current terms, privacy statements, data retention and permitted commercial use of each provider. Cloudflare may process request logs and security telemetry under the account's settings and contractual terms. The D1 quota table stores only one aggregate counter row per API endpoint (Census place lookup, PVWatts and OpenEI); it does not store visitor IP addresses, city names, coordinates or visitor identifiers. The static price-reference JSON file is served by the same site and contains no visitor-specific inputs. List any additional service that is actually enabled in production.
